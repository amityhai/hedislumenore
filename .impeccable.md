# Design Context — QualityPulse

## Product
A HEDIS quality-measure performance dashboard for a behavioral-health managed-care
organization. Two active flows: **Overview (v2)** — a bubble-field scorecard that
drills measure → provider (CRSP) → equity stratum → member worklist — and the
**Care Action Center** — a flat worklist of open care gaps with assignment.
Other tabs (classic dashboard, measure detail, rate simulator, provider scores)
are parked while these two are redesigned.

## Audience & use cases
- **Quality improvement managers** at the health plan: scan monthly performance
  vs. benchmarks, find the measures/providers/strata driving misses, launch
  targeted interventions.
- **Care-gap coordinators**: work member-level lists, assign outreach tasks to
  named staff, track what's already assigned.
- Desktop-first office use, dense data, long sessions; occasional tablet.
  Clinical/compliance setting — numbers must be trustworthy and legible.

## Brand & tone — "Direction A · Clarity"
- Calm, clinical, trustworthy. Data legibility over decoration.
- **Brand teal** (`--c-primary: #0e8a8c`) is reserved for actions/navigation and
  never doubles as a status color.
- **Status semantics are fixed**: red = below goal, blue = at goal, green =
  above goal, amber = caution/unassigned. Workflow state (e.g. "assigned")
  uses the teal family, never green.
- Light theme only. Cool slate canvas (`--c-bg`), white cards, soft cool shadows.
- Type: **Hanken Grotesk** for UI, **Spline Sans Mono** (≤600 weight) for
  measure codes, IDs, and eyebrow labels. Tabular numerals (`.num`) for all data.
- Page pattern: mono teal eyebrow → 26px bold title → one-line subtitle.
- All colors/radii/shadows come from tokens in `src/index.css`; no hardcoded hex
  in component CSS.

## Interaction conventions
- Sample-data fallbacks keep every view demonstrable, but always announce
  themselves (amber notice with retry) — never silently fake numbers.
- Toasts come from the single app-wide `ToastProvider` (`src/components/ui/Toast`).
- Every affordance is visible at rest (no hover-only reveals) and reachable by
  keyboard; interactive rows get `role="button"` + Enter/Space.
- Primary buttons are rare — one clear next action per view; the rest are
  tonal/secondary/ghost.
- **Shape carries meaning.** Buttons *do* something and are always rounded
  rectangles (`.btn` + a variant + optional `.btn-sm`/`.btn-lg`/`.btn-icon`).
  The full-radius pill belongs to controls that *filter or describe* — status
  chips, filter pills, segmented tabs. Never round a `.btn`, never square a chip.
- Never hand-roll a button's height, radius, or fill in component CSS; extend
  the system in `src/index.css` instead. Forward navigation always uses the same
  right-arrow glyph.
